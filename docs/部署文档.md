# 系统部署说明

版本3.0，2026-11-01。推荐MySQL模式；显式JSON模式供原金融业务独立回归。

## 环境与首次启动

Python 3.10及以上、MySQL 8和现代浏览器。本机验证为Windows、MySQL 8.0.44与内嵌浏览器。金融核心仍使用标准库；MySQL及主机监测依赖见requirements.txt，ECharts离线随包提供。

在项目根目录执行：

```powershell
python -m pip install -r requirements.txt
.\启动_MYSQL.ps1 -Simulation
```

脚本默认连接127.0.0.1:3306、账号root、数据库root，隐藏输入密码，不写入源码。支持-Port、-Database、-DbUser参数；其余环境配置见.env.example。本项目不自动读取.env。

首次幂等创建15张zx_表并导入模拟数据，后续以SQL状态为准，旧JSON不会覆盖数据库。初始化由服务自动执行，也可提前运行scripts/init_mysql.py。只操作本项目zx_表，不改其他业务数据库。数据库失败时明确停止启动或写操作，不悄悄切换JSON。

登录：http://127.0.0.1:8011/login 。工作台：http://127.0.0.1:8011/app 。数字人：http://127.0.0.1:8011/assistant 。运营指挥中心：http://127.0.0.1:8011/ops 。服务只监听127.0.0.1，检查Host、Origin、Cookie及CSRF。Ctrl+C停止。同一演示库限单业务服务实例。

浏览器进入/login。自行注册后返回登录，验证新账号的0元、空流水；或显式选择共享演示体验，查看完整样本和运营大屏。未设置预置个人账号或默认登录密码。不要把数据库密码当成用户登录密码；交易确认中的123456仅是明确标示的沙箱身份因子。忘记登录密码暂需本地管理员处理，未接短信。

## 领导和经理权限

领导默认只读。经理使用独立OPS_MANAGER_PASSWORD；未设置时生成在本机.runtime/ops_manager_code.txt。不要用数据库密码代替运营口令，不要公开该文件。点击右上“领导视图”验证后可分派、开始处理、恢复演练设备和解决工单。

工单写操作携带版本，过期版本需刷新。关联设备必须有20秒内正常心跳才可解决工单。运营权限不增加金融交易权限。经理角色按浏览器隔离，重启清除；5次口令错误锁定60秒。

## 实时采集与演练

参数-Simulation开启演练流，经理也可在大屏开关。每5秒读MySQL一致性快照。模拟设备、请求与工单标记synthetic；实际应用请求与本机实测CPU/内存、MySQL查询时延分别标记。演练流不改变银行余额。设备历史样本保留24小时，金融流水及审计不按此规则清理。

时间与网点筛选联动业务、请求、工单及脱敏导出，设备为当前快照。连接失败保留最后快照并显示中断，采集超过20秒显示过期，不再标为实时。缺分母或响应数据显示空值。

## 可选DeepSeek

先运行离线规则模式。可使用`.\启动_MYSQL.ps1 -DeepSeek`隐藏输入密钥，默认模型deepseek-flash，可通过-Model指定账号当前可用模型。也支持进程环境变量。密钥可用PowerShell Read-Host -AsSecureString隐藏输入；不要写进前端、.env.example或Git。服务也支持--api-key-stdin读取一行到内存。

模型失败回退规则，实际planner_source保留在请求指标，确认请求沿用初始计划来源。现有一次真实只读调用证据不等于六场景在线评测。

## API入口

|方法|路径|用途及权限|
|---|---|---|
|GET|/api/health|运行状态、存储模式、模型标记与CSRF|
|GET|/api/tools|30项金融工具及Schema|
|GET|/api/dashboard|原金融数据全景，需已登录身份及浏览器会话|
|GET|/api/ops/snapshot?branch=all&period=7d|运营白名单DTO，需已登录身份及浏览器会话|
|GET|/api/ops/export?branch=all&period=7d|相同范围脱敏JSON|
|POST|/api/ops/login、/logout|独立口令及角色切换，需CSRF|
|POST|/api/ops/action|工单状态机与演练开关，需经理及CSRF|
|POST|/api/chat、/api/confirm|原金融计划、分级授权、会话归属及CSRF|
|GET|/api/auth/me|当前身份、CSRF及能力，匿名可读|
|POST|/api/auth/register|注册及独立零余额账户；需MySQL和CSRF|
|POST|/api/auth/login|用户名密码登录，轮换会话|
|POST|/api/auth/demo|明确选择共享演示身份|
|POST|/api/auth/logout|撤销当前登录，清除Cookie|
|POST|/api/assistant/chat|知识咨询或受约束业务办理；需登录|
|GET|/api/conversation|恢复当前浏览器的对话和待确认步骤|
|POST|/api/conversation/new|开始新对话；待授权任务需先完成或取消|

运营接口不返回原始客户标识、设备IP、对话和token。客户工作台办理时必要的收款人信息仍在授权确认中展示，不是公开管理报表接口。

## 备份与离线模拟时钟

停止业务服务后备份状态与审计。MySQL逻辑备份示例，密码交互输入：

```powershell
New-Item -ItemType Directory -Path '.runtime/backups' -Force
mysqldump --user=root --password --single-transaction --result-file=".runtime/backups/bank_backup.sql" root
```

备份包含整个root演示库的模拟内部状态、身份密码派生值及会话摘要，不能公开上传。恢复前核对目标库与备份日期并停止服务，避免覆盖办理中的数据。恢复属于管理员操作，不由Agent执行。

推进生日演练前停止服务，给命令进程提供相同MySQL配置和密码：

```powershell
python scripts/run_due.py --storage mysql --at '2026-11-08T12:00:00+08:00'
```

这只执行本地模拟到期任务并事务持久化，不连接商户或真实银行。

登录会话可在有效期内跨服务重启，对话与未确认计划不会自动恢复或执行。已授权的定时任务持久化并按所属账户执行。运营访问只对演示身份开放，经理仍需独立口令。MySQL升级增加zx_auth_identities、zx_auth_sessions、zx_auth_attempts，迁移编号5，不覆盖旧账户和流水。不要并行启动两个业务服务连接同一演示库。

## JSON兼容与故障处理

```powershell
python backend/server.py --port 8011 --storage json
```

该模式只支持明确选择演示身份后的金融流程及本地数字人问答，使用.runtime/bank.json和audit.jsonl，不提供注册、账号登录或运营大屏。JSON重置先停止服务并改名备份，不用它覆盖已有SQL状态。

端口冲突则改端口；依赖缺失先安装requirements；认证失败检查MySQL服务、主机端口和环境变量，不打印密码。工单版本冲突先刷新，设备工单检查心跳。状态版本冲突需重启单实例服务，不能通过清空库解决。

root是本机用户指定的演示配置，生产应采用专用最小权限账号、凭据管理、IAM、真实MFA、受审计网关、事务账本、外部幂等与清算对账。未接真实设备协议、银行或商户，未部署公网金融服务；其他操作系统需执行自己的测试。更完整的设计、数据口径和来源见MySQL与运营大屏技术说明。
